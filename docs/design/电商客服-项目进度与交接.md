## 三、已经定下来的决策

### 意图与出口

- **12 个意图**：政策问答、商品规格、优惠券活动、会员权益、订单查询、物流查询、库存价格、退款申请、价保申请、订单变更、投诉、闲聊
- **5 个出口**：A 知识 / B 数据 / C 规则 / D 转人工 / E 兜底
- **「其他」不是意图**，是分类失败的默认值
- **四对易混边界规则**：规格vs库存、订单vs物流、退款vs变更、政策vs优惠券
- **判定顺序**：兜底 → 风险 → 处理方式
- **E 出口三个脚本**：社交回应 / 确认致谢 / 无法处理

### 兜底（A 出口证据不足）

- 方案 **C：模板 + 变量**，零模型调用
- 三个槽位：`topic`（query 截取）/ `next_step` / `top1_title`
- 必做：落池 + 给可点击动作（`transfer_human`）
- **召回快照三态**：`[...]` 调阈值 / `[]` 补知识库 / `null` 非知识缺口

### 数据

- **6 篇文档**：returns / shipping / invoice / member / promo / products
- **法规只取 5 条**：第 6/7/8/10/12 条（七日无理由暂行办法 2020 修订）
- **6 个 SKU**：推车 ST-20/ST-60、安全座椅 CS-04/CS-12、辅食机 FB-10/FB-30
- **4 张业务表**：orders / logistics / stock / coupons（各 5–20 条，重状态覆盖）
- **3 组规则**：退款资格 / 价保 / 订单变更
- **企业实践三条**：结构化优先、文档 frontmatter、答案三条硬规则
- **不做的**：白话摘要先测再加；商品参数追交叉度不追字数

### 产品定位（2026-10-28 定）

**C 端消费者自助客服**（不是 B 端坐席台）。

- 界面：聊天窗 + 轻量进度提示
- C 出口 8 状态等深度设计**保留**
- **B 端坐席助手**：不在本项目范围，作为后续配套（同一套后端换前端）
- **连带调整**：C5 总超时 60s → **30s**（消费者耐心边界，15s 给进度提示）；上线前实测 P95，必要时下调 `max_agent_steps`

详见[工程与交付设计 L0](./电商客服-工程与交付设计.md)。

### 数据飞轮

- **F1** 批处理（非实时）
- **F2** LLM 归一化 + embedding 二次校验（阈值初定 0.9）
- **F3** 写回独立 FAQ 表（可回滚），检索时合并
- **F4** 驳回即终审，不复活
- **验证**：补库前后同批题对比，库外题拒答率应保持不变
