## 一、一页主线

```
用户一句话
  → 会话层（锁 / 历史 / 落库）
  → 指代消解（失败回落原句）
  → 意图分类（12 类）
  → 路由到 5 个出口
      A 知识：检索 → 证据闸 → 生成 / 兜底
      B 数据：抽取 → 校验 → 查库 → 模板
      C 规则：抽取 → 校验 → 查单+政策 → 判定 → 算钱 → 复核 → 回复
      D 人工：固定话术 + transfer_human（当前不建单）
      E 兜底：gate → 只读 ReAct / 脚本
  → 输出检查（金额 / 措辞 / 泄露）
  → SSE
```

**记法**：意图回答“用户要什么”，出口回答“系统怎么处理、失败怎么办”。

## 二、章节卡片

### Ch02 · 主流程骨架 / 路由 / 检索 / 证据闸

| 格 | 内容 |
|---|---|
| **问题** | 用户一句话要路由到正确出口；知识型问题还必须先找到证据、再决定能不能答，避免拿不相关资料硬答。 |
| **机制** | 12 意图 → 5 出口；A 出口：dense 检索 top5 → 三态证据闸（0.55 + 边界语义自评）→ strong 生成 / weak 兜底转人工。 |
| **取舍** | dense 比 hybrid 少一套 BM25/RRF 维护，实测没有可测损失；机械闸只看 top1，便宜但会漏，所以边界带加一次语义自评；语义闸增加边界样本的延迟/成本。 |
| **证据** | dense 1.00 / hybrid 1.00 / bm25 0.76（42 条）；35 条稀有词：1.00 / 1.00 / 0.97；闸 42/42 放行、8/8 域外拦住；知识要点 40/40；确定性 44/44。 |

**关键决策**

| 决策 | 选择 | 为什么 |
|---|---|---|
| 意图分类 | 模型 + function calling | 口语化说法多；规则覆盖不完；多意图/近义边界难分 |
| 出口数量 | 5 个，按失败方式分 | 订单/物流/库存都是“查不到别猜” → B；退款/价保/变更都是“判定+复核” → C |
| 检索策略 | dense | 42 条上 dense/hybrid 不可区分，bm25 明显差；35 条稀有词复核仍无显著优势，选简单 |
| hybrid 融合 | RRF(k=60) | BM25 分数无界、cosine 0–1，线性加权要先归一化+调权重；RRF 只看排名 |
| 证据闸 | 0.55 + 边界语义 | 机械闸只看 top1，0.566 与 0.572 分不开；边界带调一次证据自评 |
| 多意图 | 只产 `multi_intent` 信号 | Ch02 单轮，没有 `pending_question`，追问后接不回来；Ch05 才消费 |

**常见追问**

- **为什么 dense 不选 hybrid？** 不是 dense 更准，是两者打平、hybrid 多维护一套索引。
- **为什么 RRF 不用分数加权？** 量纲不可比；归一化和权重都要拍脑袋。
- **机械闸为什么只看 top1？** 便宜、可标定；风险是 top1 通用块/话题近没答案，所以有语义闸和语料优化。
- **语义闸为什么只处理 `[0.55,0.60)`？** 0.60 以上不值得再问，0.55 以下问了也大概率 weak，只有边界可能翻转。
- **多意图为什么不直接追问？** Ch02 没有持久化等待状态，追问后的下一轮接不回来。

### Ch03 · C 出口（退款）

| 格 | 内容 |
|---|---|
| **问题** | 退款是资金决策：既要判断资格，又要算出可复算金额，还要可审计，不能只依赖模型。 |
| **机制** | intake → extract → validate → query_data（订单 + 政策）→ judge → compute → compliance → respond；一致放行，分歧转人工，规则 `None` 不否决模型。 |
| **取舍** | 规则维护、模型调用延迟/成本、分歧转人工降低自动化率；换来错退风险可控、结论可审计。 |
| **证据** | 简单组 19/20；dev 10/10；held-out 15/15；流水线 8/10、13/15；金额合同 10/10；T04/T05 说明“模型对、规则错、转人工”。 |

**关键决策**

| 决策 | 选择 | 为什么 |
|---|---|---|
| 判定方式 | 模型判定 + 规则复算 + compliance | 模型覆盖长尾；规则可复算、可审计；分歧不站队，转人工 |
| 规则顺序 | 状态 1–5 先于类别 6 | 顺序即业务；已发货未签收 + 定作 → `reject_then_refund`（B07/seed 1108 口径） |
| 规则 `None` | 不否决模型 | 代码不知道答案，就没有否决权 |
| 低置信 | `confidence < 0.6` → 转人工 | 模型自己说信息不足，不应硬判；此时规则还没跑 |
| 金额计算 | 纯函数 `compute_amount` | 无 IO/随机/时间；可逐条对拍；金额单位是分 |
| 部分退款 | `floor(实付 × 退件数 / 总件数)` | 宁可少退一分，不多退一分；避免浮点误差 |
| `need_info` | 用户能补的错误 | 缺单号/原因、查不到/非本人（不暴露）、重试 2 次 |
| `transfer` | 用户补不了的错误 | 日期倒挂、政策检索为空、低置信、格式错、分歧/红线 |

**常见追问**

- **为什么流水线低于模型？** 模型判对、规则判错 → compliance 分歧 → 转人工；差额是安全网代价，不是模型错。
- **为什么模型不能顺便算金额？** 模型算术不稳定、单位不确定、部分退款规则不一定知道；纯函数才能逐条对拍。
- **为什么规则返回 `None` 不否决？** 代码判不了，没资格否决；否则会把模型可能正确的结论升级成人工。
- **为什么低置信不交给规则兜底？** 规则也可能错/也可能 `None`；转人工是把不确定性显式暴露。
- **定作 + 未签收到底退不退？** 当前项目按状态优先走 `reject_then_refund`；真实业务更可能是人工协商/扣定制损失。这是已知业务边界，改的话要同时改规则表、B07/seed、prompt、评测。

### Ch05 · 多轮与上下文 + E 出口只读 ReAct

| 格 | 内容 |
|---|---|
| **问题** | 单轮图无法接住“补订单号/选卡片/改话题后再回来”；同一会话并发会互相覆盖；E 出口的长尾数据问题需要工具循环，但不能让模型写数据。 |
| **机制** | DB 三字段 `active_flow / pending_question / draft`；下一轮 `slot_fill` 补槽，`draft.intent` 反查 `resume_route`，从原出口重走；窗口 + 摘要控制上下文；会话锁串行；E 出口 gate → 只读 ReAct / 脚本。 |
| **取舍** | 用三字段而不是 checkpointer：只恢复出口所需状态，避免双写；park 保留旧流程，但新流程需要追问时会替换；锁是单进程，多 worker 要换 Redis；摘要省 token，但会丢细节；ReAct 只读，牺牲长尾写能力换安全。 |
| **证据** | 六条场景：跨轮退款、park 再回来、串轮污染、指代消解、ReAct 双工具、问候；窗口/摘要/锚点/锁/白名单均有单测；当时全量 829 passed；普通退款中位 3.62s、ReAct 中位 2.59s。 |

**关键决策**

| 决策 | 选择 | 为什么 |
|---|---|---|
| 跨轮状态 | DB 三字段 | 只恢复“在等什么、已有什么、回哪个出口”；checkpointer 会存整张 state，形成双写 |
| 恢复方式 | 出口级重走 | 节点级 resume 没必要；重跑 validate/query 便宜且避免过期快照 |
| 用户中途换话题 | park | 直接清掉会让用户重说；新流程自己也要追问时才 replace |
| 会话锁 | 进程内，5s | 防同会话并发读写；等不到返回 429；多 worker 需换 Redis/advisory lock |
| 窗口 | 摘要 + 最近原文 | 控制 token/成本/延迟；摘要边界只前移，关键实体另存 draft |
| E 出口 ReAct | 只读 + 4 步封顶 | 模型不可信；写操作需要确认/幂等/权限/审计，不能放进自由循环 |
| 结构化选择 | `selected_action` + pending 槽 | 卡片不是自然语言，重新分类会丢动作；显式恢复更稳 |

**常见追问**

- **为什么不用 checkpointer？** 跨轮只需出口级状态；checkpointer 存整个 state，和 DB 双写易不一致。
- **park 和 replace 的区别？** 新请求能直接完成 → park 旧流程；新请求自己也要追问 → replace 旧流程；完成/取消/转人工 → clear。
- **为什么锁是 5s？** 普通一轮约 4–5s，5s 是等待预算；超时返回 429，不无限排队。
- **多轮和多步的区别？** 多轮是跨请求的 turn；多步是一轮内 ReAct 的 step。
- **为什么选择卡片不重新分类？** `pending_question` 已说明在等 order_id，`draft.intent` 已说明回 rules；重新分类可能把结构化动作当闲聊。
- **ReAct 为什么只读？** 写操作不可逆，需要确认、幂等、权限、审计；白名单在代码里，模型看不到写工具。

## 四、三个 3 分钟故事

### 故事 1：B1 缺 7 天窗口

- run-01：`退货政策是什么` correctness 0.3；
- 原因：top5 只命中“不适用商品”，7 天规则排第 8；
- 修法：15 条 FAQ，用户问法做标题，chunk 42→57；
- 结果：0.3→1.0，B1 0.92→0.99，recall/context_recall→1.0；
- 反思：宽泛问法需要“入口块”，不是模型不会答。

### 故事 2：语义证据闸

- 机械闸 0.55：`能分期付款吗` 0.572 放行，`FB-30 保修多久` 0.566 也放行；
- 两条分数只差 0.006，单阈值分不开；
- 修法：边界带 `[0.55,0.60)` 调一次证据自评，3s、不重试、fail-closed；
- 结果：可答 42/42、域外 8/8、边界 4/4；阈值曲线双零区间 0.53–0.56；
- 反思：机械闸负责粗筛，语义闸只处理真正模糊的样本。

### 故事 3：B07 与 H06 的 gold 冲突

- 确定性回归 B07 掉到 43/44；
- B07/seed 1108：已发货未签收 + 定作 → `reject_then_refund`；
- H06/T01 gold：写成 `not_applicable`；
- 两份 gold 对同一条业务规则判断相反；
- 修法：按规则表/B07 统一 H06/T01/T03，prompt 恢复状态优先；
- 反思：评测集本身也会错，必须交叉校验；改 test 要按纪律迁移，不能只改 gold。

## 五、常见困惑 Q&A

**Q：gold 和 seed 有什么区别？**
gold 是人工标准答案；seed 是数据库测试数据。一个管“应该怎样”，一个管“有什么”。

**Q：dev 和 test 有什么区别？**
dev 可参与调参；test 只跑不改。B1 的 10 条全是 dev，所以 B1 提升是 dev 分数，不是盲测泛化。

**Q：为什么跑分显示 10/44？**
旧代码对 44 条都写指标行，其中 34 条 NULL；新代码只给有证据的 10 条写行。NULL 不参与均值，只是覆盖率展示问题。

**Q：为什么流水线低于模型？**
模型对、规则错 → compliance 分歧 → 转人工；不是模型退化。

**Q：为什么规则 `None` 不否决模型？**
代码不知道答案，没有否决资格；但它不等于“模型永远对”，低置信/格式错/红线仍会转人工。

**Q：为什么金额用 floor？**
单位是分，宁可少退一分；floor 保证不超退，且避免浮点误差。

**Q：为什么 D 出口不建工单？**
设计过，但实现推迟；写操作需要确认 + `request_id` 幂等 + 超时兜底。当前只发 `transfer_human` 动作。

**Q：为什么 held-out 不叫盲测？**
运行后修正过 T01/T03 的 gold，且修改前看过结果；只能叫 held-out 验证。

**Q：为什么跨轮用 DB 三字段，不用 checkpointer？**
只需恢复“在等什么、已有什么、回哪个出口”；checkpointer 会存整个 state，和 DB 双写易不一致。

**Q：用户中途换话题，旧流程会丢吗？**
新请求能直接完成 → park 保留；新请求自己也要追问 → replace；完成/取消/转人工 → clear。

**Q：多轮和多步有什么区别？**
多轮是跨请求的 turn；多步是一轮内 ReAct 的 step。不要用 ReAct 证明多轮。
