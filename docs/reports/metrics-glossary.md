# 评测指标释义

> 看 `retrieval-eval.md` 之类的报告时对照本文。每个指标都给了**我们自己的实际数值**，
> 免得"知道定义但不会读"。更新于 2026-10-30。

## 速查表

| 指标 | 一句话 | 我们的值（dense） |
|---|---|---|
| hit@k | 前 k 条里**有没有**正确答案 | hit@3 = 0.98 |
| MRR | 正确答案**排第几**（取倒数后平均） | 0.937 |
| 95% CI | 这个数字有多可信 | 0.88–1.00 |
| 不一致对数 | 两种策略"意见不同"的题数 | bm25 相对 dense 是 9 : 0 |
| 分桶 | 按能力拆开看 | policy / spec / regulation |

---

## 一、hit@k

**定义**：每道题看前 k 条里有没有正确答案，有记 1、没有记 0，然后求平均。

```
查询「退货运费谁承担」
  top1  returns#退货运费由谁承担   ← 命中
  top2  shipping#运费险
  top3  art-010
  → 这题得 1 分

查询「试穿过了还能退吗」
  top1  art-007
  top2  returns#不适用无理由退货的商品
  top3  promo#退款后券的处理
  → 正确答案（完好判定 / art-008）没进前 3 → 得 0 分
```

**我们的值**：dense 41/42 = **0.976 → 报 0.98**。

**容易混的三个**：

| 指标 | 定义 | 我们用吗 |
|---|---|---|
| hit@k | 正确答案有**没有**进前 k | ✅ |
| precision@k | 前 k 条里**有几条**是对的 | ❌ 需要标注所有正确项 |
| recall@k | 召回了几成正确项 | ❌ 同上 |

我们把 `expect_id` 改成 `expect_ids`（允许多个正确答案都算对），就是在往 recall 靠一点。

**为什么是 k=3**：候选取 5 条给生成用，但引用展示和人工检查主要看前 3；k 越大越容易"蒙对"。

---

## 二、MRR（Mean Reciprocal Rank）

**定义**：看正确答案排第几，取 `1/rank`，没召回到记 0，然后平均。**只看第一个正确答案。**

| 正确答案排名 | 得分 |
|---|---|
| 第 1 名 | 1.00 |
| 第 2 名 | 0.50 |
| 第 3 名 | 0.33 |
| 没进候选 | 0 |

**我们的值**：dense **0.937** → `1 / 0.937 ≈ 1.07`，**平均排在 1.07 位**（大多数题就是第 1 名）。
bm25 是 0.649 → 平均 1.54 位。

### 为什么 hit@k 不够

```
A 策略：正确答案排第 1  → hit@3 = 1，MRR = 1.00
B 策略：正确答案排第 3  → hit@3 = 1，MRR = 0.33
```

**hit@3 看不出差别，MRR 一眼看出。**

### 一个恒等关系

> **MRR ≤ hit@k**（k ≥ 1）

命中时 `1/rank ≤ 1`，没命中时两者都是 0。**哪天 MRR > hit@k，就是代码算错了。**

### 为什么对我们尤其重要

证据闸只看 top1（`hits[0]["similarity"]`）。**正确答案排第 1，闸才是在判断正确的那条。**

实测见过反例：`多少钱包邮` 的 BM25 结果里，第 1 名是 `promo#本文档不提供什么`，真正相关的 `shipping#包邮门槛` 排第 4。

## 三、95% CI（Wilson 置信区间）

**定义**：这个观测值有多可信——真实能力大概落在哪个范围。**样本越少，区间越宽。**

### 我们的实例：41 道命中 / 42 道题

```
p = 41/42 = 0.976190，z = 1.96（95%）

center = (p + z²/(2n)) / (1 + z²/n)          = 0.936285
margin = z·√(p(1-p)/n + z²/(4n²)) / (1 + z²/n) = 0.059500

CI = 0.936285 ± 0.059500 = [0.8768, 0.9958] → 报 0.88–1.00
```

### 为什么不用 `p ± 1.96σ`

代入得 `[0.9301, 1.0223]`——**上界超过 100%**。p 贴到 1 时正态近似失效。

Wilson 的做法是两边同除 `(1 + z²/n)`，把结果压回 `[0,1]`，代价是中心点往 0.5 挪一点、区间略宽。

### 一个更好记的理解：伪计数

```
(41 + 1.92) / (42 + 3.84) = 0.936285   ← 与 center 完全相同
```

**相当于给数据"加 1.92 次成功、1.92 次失败"再算比例。** 样本越大，这 3.84 越不显眼。

### 区间宽度取决于两件事

| 因素 | 影响 |
|---|---|
| n 越大 | 更窄 |
| p 越接近 0 或 1 | 更窄 |

所以同一个 n=42：

| 策略 | p | 区间 |
|---|---|---|
| dense | 0.98 | ±0.06 |
| bm25 | 0.76 | ±0.13 |

**命中率高的时候区间反而窄**——"接近满分"本身信息量大。

### 常见误读

> ❌ "95% CI = 下次测试有 95% 概率落在这个区间"
> ✅ "重复采样很多次，95% 的区间会包含真实值"

## 四、不一致对数（配对比较 / McNemar）

**定义**：同一批题上比两种策略，**只数"一个找到一个没找到"的题**，打平的丢掉。

| | B 命中 | B 未命中 |
|---|---|---|
| **A 命中** | 不计数 | 记给 A |
| **A 未命中** | 记给 B | 不计数 |

**为什么丢掉打平的**：42 道题里 30 道两种都能找到，这 30 道只说明题目简单，跟策略优劣无关。丢掉了，比较才灵敏。

### 显著性门槛

原假设下每个不一致题五五开，全部押一边的概率：

```
p = 2 × (1/2)^n
```

| 不一致对数 | p | 结论 |
|---|---|---|
| **9 : 0** | 0.0039 | ✅ 显著 |
| 6 : 0 | 0.031 | ✅ 刚好显著 |
| 5 : 0 | 0.063 | ❌ |
| 8 : 3 | 0.23 | ❌ |
| **1 : 0** | 1.00 | ❌ 毫无意义 |

**经验规则：单向差 6 条以上才勉强能说"更好"。**

### 我们的读法

| 显示 | 含义 |
|---|---|
| `9 : 0（显著）` | dense 独赢 9 条，bm25 一条没赢 → **BM25 确实更差** |
| `1 : 0（不显著）` | 只有 1 条不一致 → **什么也说明不了** |

所以结论写的是"hybrid 与 dense 在噪声内不可区分，按选简单的定 dense"，**不是**"dense 更好"。

## 五、分桶（bucket）

按"考什么能力"分组，**防止总分掩盖某一类全错**。

| 桶 | 含义 | 题数 | 查询数 |
|---|---|---|---|
| `policy` | 平台政策：退货 / 运费 / 发票 / 会员 / 优惠券 | 8（P1–P8） | 24 |
| `spec` | 商品规格：型号、参数、交叉点 | 3（S1–S3） | 9 |
| `regulation` | 法规条文：内容与条号 | 3（R1–R3） | 9 |
| `refuse` | 该拒答的问题 | 1（N1） | 3（**不计入检索指标**） |

### 每个桶考什么

| 桶 | 依赖的能力 | 例子 |
|---|---|---|
| policy | **语义匹配**（问法和原文几乎没有共同词） | 「买回来不想要了还能退吗」→「7 个自然日内可申请」 |
| spec | **字面精确**（型号是稀有 token） | 「FB-30 保修多久」→「FB-30 … 保修：24 个月」 |
| regulation | **条号 + 法律术语** | 「七日是从签收当天算还是第二天」→ art-010 |

### 实际效果

bm25：spec **9/9**、regulation **6/9**、policy **17/24**。
**只看总分 0.76 完全看不出"法规类是短板"**——这就是分桶的价值。

### 局限（必须记住）

每桶只有 9 条查询，**置信区间约 ±30pp**。

| 能不能说 | 结论 |
|---|---|
| ❌ "hybrid 在 regulation 上比 bm25 强一倍" | 9 条题看不出这么细 |
| ✅ "regulation 类 BM25 明显吃力" | 6 vs 9 的差距够大，可当线索 |

**分桶用来"发现问题在哪"，不是"证明某个策略在某类更优"。**

---

## 六、读报告的三步法

1. **看 CI 有没有重叠** → 重叠就别比大小
2. **看不一致对数** → 少于 6 条别下结论
3. **看失败样本** → 具体哪几条错了，比总分有用得多
