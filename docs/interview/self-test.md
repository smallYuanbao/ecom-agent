# 面试自测方法

> 用途：不靠"读一遍文档"，靠**闭卷输出 + 对照 + 代码定位**发现漏洞。
> 配套：[ch01](./ch01-data-foundation.md) / [ch02](./ch02-retrieval-skeleton.md) / [ch03](./ch03-refund.md) / [ch04](./ch04-data-exit.md) / [ch05](./ch05-multi-turn.md)

---

## 一、三种自测，缺一不可

| 方式 | 练什么 | 怎么做 |
|---|---|---|
| **闭卷复述** | 表达的条理性 | 30 秒讲完一章，录音 |
| **随机抽题** | 临场反应 | 从追问清单随机抽 5 题，不看答案 |
| **代码定位** | 真实性 | 听到关键词，30 秒内说出文件 + 函数 |

只看文档会给自己"我懂了"的错觉；**说出来**和**指到代码**才是真的会。

---

## 二、每题的评分标准（0–3 分）

| 分 | 标准 |
|---|---|
| 0 | 答不上，或者只说"做了 XX" |
| 1 | 能说结论 |
| 2 | 结论 + **为什么这样做** + **一个数字** |
| 3 | 再加 **代码位置** + **代价/边界** |

**目标**：
- 核心 10 题 ≥ 2 分
- 每章至少 3 题到 3 分

### 示例：为什么用部分唯一索引？

| 分 | 回答 |
|---|---|
| 0 | 「为了幂等。」 |
| 1 | 「用部分唯一索引做消息幂等。」 |
| 2 | 「普通唯一索引下多条 NULL 也会冲突，部分索引只约束非 NULL 行；这样没带幂等键的消息可以有多条。」 |
| 3 | 「代码在 `app/db/schema.sql` 的 `uk_msg_idem`；代价是要记住'部分索引只在 SQLite/PG 支持'，换库要确认语法。」 |

## 四、15 分钟模拟面试脚本

让朋友（或录音）按这个顺序问，**不要提前给题**：

| 时间 | 问题 | 考察 |
|---|---|---|
| 0–1 min | 「介绍一下这个项目」 | 30 秒版本 |
| 1–4 min | 「为什么退款用 Workflow 不用 Agent？数据查询为什么连模型都不用？」 | 架构取舍 |
| 4–7 min | 「模型判错了怎么办？」 | 安全设计 |
| 7–10 min | 「你怎么知道模型判得准？」 | 评测 |
| 10–11 min | 「多轮状态怎么恢复？为什么不用 checkpointer？」 | 架构边界 |
| 11–12 min | 「困难组才 10 条，够吗？」 | 边界意识 |
| 12–14 min | 「这个项目最大的瓶颈在哪？」 | 反思能力 |
| 14–15 min | 「如果继续做，下一步做什么？」 | 规划 |

> 最后两题最容易被忽略，也最能拉开差距。答案在
> [ch03-refund.md](./ch03-refund.md) §4.4 / §6、[ch05-multi-turn.md](./ch05-multi-turn.md) §2。

## 五、5 分钟现场演示脚本

如果面试官说「能跑一下吗」，按这个顺序，**每步都有明确看点**：

```bash
# 0. 起服务（提前起好，别现场等）
uv run uvicorn app.main:app --port 8000

# 1. 知识出口：有引用、有角标
curl -N -X POST localhost:8000/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"退货政策是什么"}'
# 看点：route=knowledge；delta 里有 [1][2]；citations 非空

# 2. 退款成功：金额只出现一次
curl -N -X POST localhost:8000/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"订单1002 不想要了"}'
# 看点：route=rules；金额 1249.00 元；action=transfer 视情况

# 3. 数据查询：零模型、模板回答
curl -N -X POST localhost:8000/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"订单1001 到哪了"}'
# 看点：route=data；金额/单号逐字来自库；没有模型生成痕迹

# 4. 缺单号：列候选，不是文字追问
curl -N -X POST localhost:8000/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"我要查订单"}'
# 看点：actions.type=select_order；3 个候选；本轮结束

# 5. 转人工：能说清是哪一类
curl -N -X POST localhost:8000/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"用了一下，不太确定算不算用过，能退吗"}'
# 看点：低置信度 → 转人工，不是硬判

# 6. 多轮：跨轮接续（用脚本，保留 conversation_id）
uv run python scripts/try.py chat "我要退款，尺寸不合适"
# 再输入：1002
# 看点：第二轮直接判定，不再问原因；route 帧 resumed=true
```

**多轮演示只看三件事**：`resume_flow` 提示有没有出现、第二轮有没有重复问、`route.resumed` 是否为 true。

**演示时只说三件事**：这条走了哪个出口、为什么、结果对不对。
不要边跑边翻代码。

## 六、高频扣分点

| 扣分点 | 典型表现 | 改法 |
|---|---|---|
| 只讲"做了什么" | 「我用了 LangGraph」 | 加"为什么不用另一个方案" |
| 数字没出处 | 「准确率 90%」 | 说清样本量、指标定义、哪份报告 |
| 把没做的说成做了 | 「用了 interrupt」「支持多意图」 | 承认边界 + 说下一步 |
| 讲框架不讲设计 | 「用了 RAG / ReAct」 | 讲选型依据和代价 |
| 答不出代码位置 | 说"在某个文件里" | 提前记 10 个关键符号 |
| 遇到不会的硬编 | 开始绕 | 「这块我没做，我的判断是…」 |
