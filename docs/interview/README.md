> 每章一份，格式统一：**30 秒版本 → 关键决策 → 踩坑故事 → 追问清单 → 不要说的话 → 数字速查**。
> 原则：每条结论都能在 `docs/reports/` 找到出处；没有出处的数字不写。

## 怎么用

1. **面试前 10 分钟**：只看每份的「0. 30 秒版本」和「数字速查」；
2. **简历写完**：对着「追问清单」逐条自问，答不上来的回代码里补；
3. **正式准备**：按 [self-test.md](./self-test.md) 的三天计划做闭卷自测；
4. **被问住了**：先承认边界（样本量、未做的部分），再讲下一步计划——比硬答得分高。

## 跨章的主线

| 主线 | 出现在 | 一句话 |
|---|---|---|
| **确定性 vs 模型** | Ch02 路由、Ch03 判定、Ch04 零模型 | 能查表的不让模型决定；模型只做理解和表达 |
| **fail-closed** | Ch02 证据闸、Ch03 三处闸、Ch04 工具异常 | 拿不准就拒答 / 转人工，不硬给结论 |
| **评测要能区分被测对象** | Ch02 三策略、Ch03 两组 gold set | 规则满分时要另造难题，否则测不出模型价值 |
| **失败样本比总分有用** | 全章 | 每条未命中的归因（模型 / 规则 / 数据）决定下一步修什么 |

## 新增一章时

- 复制一份现有文档的六节结构
- 数字必须能指到 `docs/reports/` 的具体文件
- 在本文件和 [reports/README.md](../reports/README.md) 各登记一行
