> 「第二章把主流程骨架立起来：**5 个出口 + 12 类意图查表路由**。
> 意图由模型分类，但**路由是查表**，模型不参与决定去哪个出口。

> - 证据闸校准：选 0.55，可答题全放行，域外只漏 1 条；
> - 质量传导四格：最危险的「检索没命中、答案却很完整」是 **0**。」

## 1. 架构：五出口 + 查表路由

```
resolve_reference → classify_intent → route_by_intent
                                          │
        ┌──────────┬──────────┬───────────┼──────────┬──────────┐
     knowledge    data      rules       human     fallback
```

**关键设计：模型只分类，不决定路由。**

```python
route = INTENT_TO_ROUTE.get(intent, FALLBACK_ROUTE)
```

| 做法 | 问题 |
|---|---|
| 模型直接输出 route | 多一层不可控；同一个意图可能被映射到不同出口 |
| **模型输出 intent，代码查表** | 路由可枚举、可测试、可审计 |

> **面试可讲**：「分类可以模糊，路由必须确定。模型越界就落兜底，不会抛 KeyError。」

**12 类意图**：政策问答 / 商品规格 / 优惠券 / 会员 / 订单查询 / 物流 / 库存价格 /
退款申请 / 价保 / 订单变更 / 投诉 / 闲聊，外加兜底「其他」。

## 2. 检索选型：为什么是 dense

### 2.1 评测集

- 14 道基础题 × 3 种问法（口语 / 正式 / 多意图）= **42 条查询**
- 指标：hit@3（取回 5 条，看前 3 条有没有命中）
- 拒答题不计入检索指标（它们由证据闸处理）

### 2.2 结果

| 策略 | hit@3 | 95% CI | MRR | 相对 dense 不一致对数 |
|---|---|---|---|---|
| **dense** | **1.00** | 0.92–1.00 | **0.948** | — |
| bm25 | 0.76 | 0.61–0.87 | 0.633 | 10 : 0（显著） |
| hybrid | 0.95 | 0.84–0.99 | 0.939 | 2 : 0（不显著） |

**分桶**（policy / regulation / spec）：

| 策略 | policy | regulation | spec |
|---|---|---|---|
| dense | **24/24** | **9/9** | **9/9** |
| bm25 | 17/24 | 6/9 | 9/9 |
| hybrid | 22/24 | 9/9 | 9/9 |

**结论**：语料只有 42 个 chunk、专有名词少，dense 已经满分；
hybrid 没有统计显著优势，却要多维护一套 BM25 索引。**选 dense，不做参数堆叠。**

> **面试可讲**：「不是 hybrid 不好，是这批语料上它没有带来可测量的收益。
> 我用的是不一致对数（McNemar 的思路），不是只看总分。」

### 2.3 分问法的发现

| 策略 | colloquial | formal | multi |
|---|---|---|---|
| dense | 16/16 | 25/25 | 1/1 |
| bm25 | 9/16 | 22/25 | 1/1 |
| hybrid | 15/16 | 24/25 | 1/1 |

**BM25 在口语问法上掉得最狠**（9/16）——用户不会用「七日无理由退货」这种词。

## 3. 证据闸：阈值 0.55 怎么来的

### 3.1 判定矩阵

阈值 `0.55`，dense，42 条可答 + 3 条该拒 + 8 条域外：

| 类型 | 条数 | 放行 | 拦住 |
|---|---|---|---|
| 可答题 | 42 | **42** | 0 |
| 该拒答 | 3 | 0 | **3** |
| 域外探测 | 8 | 1 | **7** |

唯一漏放：`能分期付款吗` → 0.572，命中了会员积分规则。

### 3.2 阈值不是"手调"出来的

把 50 条样本的 top1 分数排序，逐个试阈值，**只有跨过观测分数时行为才变**：

| 阈值 | 可答题放行 | 负样本拦住 | 代价 |
|---|---|---|---|
| 0.566 | 42/42 | 10/11 | 不用代价 ← 当前 0.55 行为相同 |
| 0.591 | 41/42 | 11/11 | 少答 1 条 |

**Pareto 前沿只有两个点。** 0.55 和 0.566 行为完全一样——
它落在两个相邻观测分数之间，微调没有任何区别。

> **面试可讲**：「阈值不是连续可调的。数据里只有几个真正改变行为的点，
> 我按 Pareto 前沿选，而不是拍一个 0.5。」

### 3.3 方向：fail-closed

可答题最低 0.566、域外最高 0.572，**两者重叠**。
任何单一阈值都要在「多拒」和「多放」之间选一边。方向是宁可拒，不硬答。

## 4. 知识出口评测

| 指标 | 值 |
|---|---|
| 引用覆盖率 | 42/42 = 100% |
| 要点全覆盖率 | **39/40 = 98%** |
| 闸放行率 | 42/42 = 100% |

### 质量传导四格（检索命中 × 答案覆盖全部要点）

|  | 答案覆盖全部要点 | 答案缺要点 |
|---|---|---|
| **检索命中** | 39 | 1 |
| **检索未命中** | 🚨 **0** | 0 |

**最危险的一格为空**：没有出现「检索没找到、答案却很完整」——那意味着模型在编。

> **面试可讲**：「RAG 评测不能只看答案像不像。要拆成两件事：
> 检索有没有找到、答案有没有用上。四格能区分'检索差'和'模型编'。」

## 5. 踩坑故事

### 5.1 分词器吞掉了关键词

- **现象**：BM25 把「包邮吗」召回到「钱包」相关文档
- **原因**：jieba 把「钱包」当成一个词，用户问句里的「包」被吞掉
- **改法**：领域词（包邮 / 退货 / 保修…）先按字面提取，再做 jieba + 停用词
- **结果**：BM25 hit@3 从 0.69 → 0.76

> **可讲**：「方案表现差时，先查预处理，再下结论。别急着换模型。」

### 5.2 证据闸阈值量纲错了

- **现象**：最初按 0.45 卡，闸永远不通过
- **原因**：拿 RRF 分数和余弦阈值比。RRF 的满分约 `1/(60+1) ≈ 0.016`，最大总和约 0.033
- **改法**：改成比较 `similarity`（余弦），重新标定到 0.55

> **可讲**：「阈值必须和指标的取值范围匹配。混用两套分数，规则永远不会触发。」

### 5.3 评测代码本身的三个 bug

| 问题 | 后果 | 改法 |
|---|---|---|
| `expect_points` 放在 case 级 | 一条查询被迫覆盖整题的所有要点 | 下放到 query 级 |
| 用字面量匹配要点 | 「不能叠加」判不出「不可叠加」，覆盖率 48% | 改成正则，覆盖率 98% |
| 排名按 `case_id:style` 做 key | 同题同风格的重复问法互相覆盖，n 被少算 | 改成按下标对齐 + 断言 |

> **可讲**：「评测代码也会有 bug。看到异常低的分数，先怀疑评测本身。」

## 6. 追问清单

| 问题 | 答题要点 |
|---|---|
| 为什么不让模型决定路由？ | 分类可模糊，路由必须确定、可枚举、可测试 |
| 为什么选 dense 不选 hybrid？ | 这批语料 dense 满分，hybrid 无统计显著收益，多一套索引成本 |
| hit@3 和 MRR 的区别？ | hit@3 看"前 3 有没有"，MRR 看"第一条命中的位置" |
| 不一致对数是什么？ | 两种策略在同一题上"一个中一个不中"的对数；比总分更能看出差异 |
| 阈值怎么定的？ | 按观测分数排序找 Pareto 前沿，不是连续调参 |
| 为什么选 fail-closed？ | 可答与域外分数重叠，宁可拒答也不硬答 |
| 检索为空怎么办？ | 证据闸拦下 → 兜底话术 + 落池；不硬答 |
| 引用角标怎么保证不越界？ | 解析时校验 `[n]` 是否在证据范围内，越界丢弃 |
| 怎么发现模型在编？ | 质量传导四格；「检索未命中但答案完整」应为 0 |
| 12 类意图够吗？ | 不够，兜底「其他」承接长尾；Ch05 再加只读 ReAct |
| 意图准确率 12/12 能说明什么？ | 只能说明标准问法；真实分布要更难的边界样本 |
| SSE 帧顺序怎么定的？ | ack → route → delta → citations → actions → done；route 先发让前端立刻有反馈 |
